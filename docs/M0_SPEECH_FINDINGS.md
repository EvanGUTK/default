# M0 local speech spike: findings

Authority: Milestone 0, "Local speech spike" (docs/ROADMAP.md). Owner: Voice specialist. Branch: `spike/m0-speech-deps`. Measured 2026-10-13. Harness: `crates/speech/`. License review: docs/M0_DEPENDENCY_REVIEW.md.

## Summary

- **Recognition is viable on CPU only, but only with a shrunk encoder window.** whisper.cpp pads every clip to a fixed 30 s window, so a 4 s utterance costs almost as much as a 30 s one. With the encoder window sized to the clip (`audio_ctx`), utterances of 2 to 4 s transcribed in about **0.3 to 0.6 s with `base.en`** (0.31 s mean for one 4.2 s clip over 10 runs; 0.62 s median across 14 clips) and about **1.0 s with `small.en`** (0.99 s and 0.97 s in the same two measurements). Without it: about 1.9 s for `base.en` and about 4.8 s for `small.en`. These figures were taken on a heavily loaded machine (see "Environment"), so treat them as upper-biased.
- **Accuracy on ordinary words is good; on this project's own vocabulary it is not.** Common phrases ("run cargo build release", "ask Claude to fix the failing TypeScript test") came out right. Novel tokens (Tauri, Codex, herdr, kubectl, pytest) were frequently wrong with `base.en` and improved but not fixed with `small.en` plus a vocabulary prompt. The test audio was synthetic TTS speech, so real microphone speech is likely worse. That was not tested.
- **Silence and non-speech need gating.** Pure silence made `base.en` output "you"; a tone fixture produced "(electronic beeping)". A Silero VAD pass rejected the tone fixture with 0 segments.
- **whisper-rs gotcha:** `FullParams::enable_vad(true)` is silently ignored when using `WhisperState::full()`. Filtering must be done by the caller. This cost one false measurement during the spike and was caught by reading the whisper.cpp source.
- **Not measured:** microphone capture, streaming or partial results, interruption (barge-in), echo, real noise, GPU, Windows, TTS.

## Latency: audio end to text out

Measured as wall time from handing the finished audio buffer to whisper.cpp until the transcript string is read, on a model that is already loaded. This is what a push-to-talk release would wait for. Capture, resampling and UI are excluded.

### Sweep over 14 clips (median of per-clip warm means)

| Configuration | Warm latency median (min to max) | Cold first run, median | Mean WER | Clips with WER 0 |
| --- | --- | --- | --- | --- |
| `base.en` | 1889 ms (1229 to 3004) | 1884 ms | 0.277 | 4 of 14 |
| `base.en` + shrunk window | **624 ms** (321 to 2283) | 630 ms | 0.319 | 4 of 14 |
| `small.en` | 4814 ms (4344 to 6618) | 5084 ms | 0.250 | 4 of 14 |
| `small.en` + shrunk window | **966 ms** (658 to 1529) | 886 ms | 0.230 | 5 of 14 |
| `base.en` + shrunk + vocabulary prompt | 369 ms | n/a | 0.293 | 4 of 14 |
| `small.en` + shrunk + vocabulary prompt | 1003 ms | n/a | **0.183** | 5 of 14 |

The wide min-to-max spread comes from machine contention, not from the clips.

### Focused run: one 4.2 s clip, 10 warm runs

| Configuration | Mean | Min | Max |
| --- | --- | --- | --- |
| `base.en`, 8 threads | 2082 ms | 1329 ms | 5722 ms |
| `base.en`, 4 threads | 1902 ms | 1585 ms | 2483 ms |
| `base.en` + shrunk, 8 threads | **310 ms** | 281 ms | 370 ms |
| `base.en` + shrunk, 4 threads | 379 ms | 343 ms | 413 ms |
| `small.en` + shrunk, 8 threads | 989 ms | 836 ms | 1273 ms |
| `small.en` + shrunk, 4 threads | 1280 ms | 1113 ms | 1509 ms |

Reading these against the roadmap target ("first spoken cloud answer aim for 3 seconds after utterance end"): `base.en` with a shrunk window leaves more than 2.5 s for the cloud request and speech output. `small.en` with a shrunk window leaves about 2 s. Unshrunk `small.en` does not fit. Thread count 8 beat 4 for `small.en`, while 4 and 8 were close for `base.en`.

The 30 s padding effect is visible in the data: 5 s of tone took 2.3 s and 11 s of real speech took 2.7 s on the same unshrunk `base.en` run.

## Accuracy on technical phrases

Word error rate after lowercasing and stripping punctuation. 14 clips, one decode each, two synthetic voices. The sample is small, so the table shows direction, not a statistic.

Transcripts of the hard phrases (`small.en`, shrunk window, with vocabulary prompt) versus `base.en` without a prompt:

| Spoken | `base.en`, no prompt | `small.en` + prompt |
| --- | --- | --- |
| open the tauri config in vs code | "Open the tour icon Fig in VS Code" / "Open the ToriConfig in VS Code" | "Open the Tori config in VS Code" |
| start a codex session in the herdr repo and run pytest | "Start a codecs session in the Herdorepo and RunP test" | "Start a Codex session in the herd repo and run pytest" (one voice) |
| kubectl get pods in the staging namespace | "Qabec will get pods…" / "QBectil get pods…" | "kubectl get pods…" (one voice), "kubectl git pods…" (other) |
| ask claude to fix the failing typescript test in use effect | correct | correct |
| run cargo build release | correct | correct |

Notes that change how to read the WER column:

- **WER overstates two phrases.** Whisper writes "dash dash release" as `--release` and "dash b" as `-b`. Normalization drops the symbols, which counts as deletions even though the output is what a developer wants. Clips p2 and p3 carry this artifact. Command-line syntax should be handled by a post-processing step, not read as recognition failure.
- **Shrinking the window cost no accuracy on average with `small.en`** (0.250 to 0.230) and a little with `base.en` (0.277 to 0.319, driven by one clip going from 0.143 to 0.571). A short clip is the case the setting targets, but whisper.cpp marks it experimental.
- **Vocabulary prompt helped** `small.en` (0.230 to 0.183) and `base.en` slightly. "herdr" was still heard as "herd" in some runs. A prompt is cheap, but a project-name list will need maintaining and testing.
- **Real speech baseline:** `jfk.wav` with `base.en` gave an exact transcript (WER 0.000), which confirms the pipeline is correct. It is one clip of clean, formal speech.
- **These are synthetic voices.** Machine-synthesized speech is more regular than human speech, and no accent, microphone, room or echo variation was tested. Expect real accuracy to be lower.

### Noise (deterministic white noise, `small.en`, shrunk window)

| SNR | "ask claude to fix…" (WER) | "start a codex session…" (WER) |
| --- | --- | --- |
| 20 dB | 0.091 ("claw") | 0.364 |
| 10 dB | 0.182 | 0.364 |
| 5 dB | 0.000 | 0.455 |
| 0 dB | 0.091 | 0.455 |

`jfk.wav` was transcribed exactly even at 0 dB and at -5 dB white noise. White noise is a weak proxy for keyboards, fans, music, or other talkers, so this shows only that the model is not fragile to broadband noise. Babble, music and echo from the assistant's own voice are untested.

| 5 s digital silence | "you" | "[BLANK_AUDIO]" |
| 5 s tone and silence | "(electronic beeping)" | not run |

With a VAD gate in front, the tone fixture produced 0 speech segments and the recognizer was not invoked. Without a gate, `base.en` can emit text for silence, which would become a spurious command.

## Voice activity detection

Silero VAD v5.1.2 run through whisper.cpp (`WhisperVadContext`), default parameters.

| Input | Result | VAD time |
| --- | --- | --- |
| Tone and silence, 5 s | 0 segments (correct) | about 120 ms |
| "start a codex session…", 4.2 s | 1 segment, 0.10 s to 3.49 s | 95 to 195 ms |
| "run cargo build release", 2.3 s | 1 segment, 0.07 s to 1.66 s | about 52 ms |
| `jfk.wav`, 11 s | 5 segments, 0.29 s to 10.59 s | 262 to 274 ms |

- Cost was roughly 20 to 25 ms per second of audio on a loaded machine, running as a separate pass over the full buffer.
- Trimming 4.2 s of audio to 3.59 s lowered `base.en` shrunk-window latency from 456 ms to 275 ms in one comparison, which is about the same as the 195 ms the VAD pass cost. For short push-to-talk clips, VAD is roughly latency-neutral; its value is rejecting empty or non-speech clips and trimming tails.
- Whisper's own `vad` parameter did nothing through the state API (see Summary). The harness runs the VAD context itself and passes only padded speech segments (0.1 s padding) to the recognizer.
- Detector thresholds were left at defaults and not tuned. Streaming VAD for hands-free end-of-utterance detection, speech overlap, noise robustness and echo rejection (the validation gates in docs/STACK.md) are untested.

## What a push-to-talk integration needs

1. **Audio capture** (not built here): 16 kHz mono f32 from the default input device through WASAPI, with a ring buffer that starts when the key goes down and stops when it comes up. The harness's `to_mono_16k` handles downmix and resampling for files; its linear resampler has no low-pass filter and must be replaced for live device rates such as 44.1 or 48 kHz.
2. **A resident recognizer.** Keep the model and `WhisperState` loaded between utterances. Load cost is 150 to 400 ms from page cache and more from cold disk, which would be visible on first use. Preload at app start, or on the first key-down.
3. **Shrunk encoder window** sized from the clip length plus padding (`Options::shrink_encoder`), with a regression test on real speech before shipping, since whisper.cpp labels it experimental.
4. **A VAD gate** before the recognizer to drop empty or non-speech clips. Without it, silence can become "you".
5. **Run inference off the UI thread and keep it cancellable.** whisper-rs inference is a blocking call. For the 250 ms stop target, run the recognizer in a supervised process or thread and discard its result on stop; a cancellation hook inside `full()` was not tested.
6. **Pre-warm during speech.** Because latency is dominated by encoder time, a possible improvement is to start decoding speculatively while the key is held. This was not tried and could waste CPU.
7. **Vocabulary support:** a maintained initial prompt for project and tool names, plus post-processing for command-line syntax ("dash dash release" to `--release`).
8. **Model management:** runtime download with checksum, size disclosure and a removal control (docs/M0_DEPENDENCY_REVIEW.md).
9. **Model choice:** `base.en` with a shrunk window for fastest response; `small.en` with a shrunk window and prompt for better technical accuracy at roughly three times the latency and memory. Offer both and measure on the target hardware.
10. **Build requirements:** cmake, a C++ toolchain, libclang for bindgen, and a Windows MSVC build. The Windows build is untested.

## Limits and what was not shown

- No microphone, streaming, partial transcripts, barge-in or echo handling. The interruption item in the roadmap evidence list is open.
- No Windows-native run; WSL2 only.
- No GPU path; no NVIDIA dependency assumed (docs/STACK.md).
- No idle-machine latency baseline.
- One decode per accuracy clip, two synthetic voices, seven phrases.
- Recognition of non-English speech was not tested (English-only models).
- TTS was not measured; see the dependency review for the recommendation and open questions.

## Reproducing

```text
cd crates/speech
scripts/fetch-assets.sh                          # models and jfk.wav into ./models (git-ignored)
cargo build --release
target/release/toby-speech-spike fixture /tmp/tone.wav
target/release/toby-speech-spike transcribe --model models/ggml-small.en.bin --wav models/jfk.wav --shrink-encoder
target/release/toby-speech-spike vad --vad-model models/ggml-silero-v5.1.2.bin --wav models/jfk.wav
WHISPER_MODEL=models/ggml-base.en.bin JFK_WAV=models/jfk.wav cargo test --release -- --ignored
```

See `crates/speech/README.md` for build prerequisites.
