# Inspiration and original work

## Reference

[Bluey by Riley](https://github.com/rbrown101010/bluey-by-riley) motivated the broad experience of a character that can attend to and interact with a computer. The user's GoodyOS screenshot motivated a clear repository presentation with a strong identity, a short promise, principles, and structured explanation.

These are conceptual references, not asset or implementation sources for Toby.

## Original branch boundary

The repository was forked, so main and Git history contain upstream work. This planning branch uses a fresh documentation tree. No upstream application source, preview image, GIF, bundled font, or build script is present in its current tree.

The upstream README and license were inspected to establish context and licensing. Source implementation files were not used as the basis for the architecture. The documents here were authored for the owner's stated goals.

The upstream declares The Unlicense. The decision to avoid reuse is the owner's preference even where a license could permit it.

## Future development

Write new implementation against this specification. Create new character art and animations. Track dependency, model, voice, and font provenance separately. If a later decision explicitly permits third-party reuse, identify exactly what is incorporated and retain applicable notices.

The final license for new Toby materials remains an owner decision. Do not relabel the whole fork history as authored by the owner or delete provenance to make an independence claim.

## Publication distinction

A fork rename changes its name, not its ancestry. If the owner later wants a standalone repository, prepare a new original tree and review the migration separately. Do not erase or rewrite historical commits as part of a routine documentation update.
